## Immutable implementation contract

1. Native interactive Pi TUI must be started as argv into the existing PTY/ConPTY (not --mode rpc, not pipe to xterm, not typed chat/HTML transcripts). Respect installed Pi providers, themes, skills, extensions, and commands; do not maintain a Lantern command/model catalog, filter capabilities for localhost, wrap every prompt in XML, or feed hidden Enter/keyboard bytes for context.
2. An opaque Lantern Pi sessionId is distinct from file path, tabId and Pi's current native session file. Creation captures canonical confined cwd, immutable contextRef(kind,path,revision, optional selection) and native session identity; Pi /new, /fork and /resume transitions must be observed through a version-tested native mechanism, not inferred from a transcript. Reopening after host restart restores Pi-native saved history and marks interrupted work, never pretends process survival. Closing one tab only detaches; explicit Close/Stop owns process teardown; ordinary host shutdown has a documented policy.
3. TerminalManager and WS own exactly one live PTY per Pi session and route output by sessionId+generation+seq. Attach is idempotent; output ack/snapshot is ordered. Exactly one client owns input/resize at a time; other viewers are read-only; explicit takeover is race-tested. Two sessions and two tabs cannot affect each other's input, stop, model, cwd or context. Apply backpressure and resource ceilings by reuse, not new unbounded registries. No Pi data in normal Terminal views/legacy broadcast.
4. A raw ANSI tail cannot be advertised as lossless replay. Phase 0 must compare screen cells (including styles), cursor, normal/alternate screen and relevant terminal modes at matching geometry; test deliberately truncated/broken escapes, in-flight tool output and different viewer widths, including known serializer right-edge case. Evaluate native @xterm/headless + @xterm/addon-serialize against the exact xterm 6 build, but do not ship a hand-written ANSI emulator or extra permanent Node service without evidence and review. If no conformant mechanism is proven, STOP Pi release and retain normal Terminal unchanged.
5. Pi works on original .md through native file tools. No modifications to lantern/live_markdown.py, lantern/working_copy.py, lantern/md_editor.py, lantern/crop.py, Markdown HTTP/routes, static/markdown_*, Milkdown, diff, plugin.py or guard extension without a separately justified narrow contract and Markdown owner decision. No view hijack, no interaction blocker merely because the editor is in Visual/Edit mode.
6. Preserve ordinary Terminal keyboard/xterm keydown and onData exactly per Spec 001 Option A: keyCode 231 and injected Backspace remain xterm-owned, and raw data is forwarded in order. Never add UniKey-specific key suppression/reordering/delay, no terminal security bypass, no unauthorized LAN policy/token quotas/new auth/sandbox. Default native Pi exposure must not extend to LAN without a separately approved enforceable boundary.
7. Maintain a useful end-user dock/expand/fullscreen native xterm beside editor without hiding active caret/diff; show path/kind, session, writer/viewer, ready/running/reconnecting/error, and accessible focus. Never restore chat tool logs from sessionStorage as a second truth.
