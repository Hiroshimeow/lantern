## Findings requiring DEV correction

**R2-1 — E2E negative script test can pass when injected resource is missing; missing proof of deliberate same-origin script blocking.** `tests/test_preview_csp_e2e.py:32-35,174-184`. Fixture creates `probe-evil.js` at the root, then uses `script.src='/probe-evil.js'`, checks only that `window.__lanternCspEvil` stays false, and requires merely *some* `Content Security Policy` error in the page. The test does not establish a successful 200/javascript fetch for the target, nor attribute the error to *that injected script*. A 404/routing error, unexecuted loader or unrelated previous CSP violation is indistinguishable from the desired denial. **Correction:** assert the target would be served as JavaScript (request/response in a direct route sanity check independent of CSP), and correlate that exact nonce-less injected `script` URL to a CSP rejection (e.g. `securitypolicyviolation` script-src disposition); check execution stays false and reject unrelated unexpected violations. Do not grant the test script a nonce.

**R2-2 — “no unexpected CSP violations” criterion is not checked; some unrelated application CSP breakage will still yield green tests.** `tests/test_preview_csp_e2e.py:149-159,162-185`. Read-only `read_console` and Markdown `md_console` each only assert `any('Content Security Policy' in line ...)` following intentionally blocked probes; the test never classifies violations by blockedURI/directive and never asserts the absence of unanticipated CSP errors. Thus unrelated app/Worker/asset failures are masked by intentionally blocked probes. Revised M-A5 in `specs/001-terminal-ime-markdown-export/spec.md:~260` explicitly requires distinguishing expected vs unexpected violations. **Correction:** capture `securitypolicyviolation` events and/or console errors with directive/resource identities and assert an explicit allowlist for intentionally blocked probes; validate app boot/Worker remained violation-free *before* negative probes; no blanket console-error suppression. Keep one disposable Edge harness rather than creating a new testing framework.

**R2-3 — “no external request escapes” watcher is restricted to a single hard-coded hostname, and cannot prove broad no-third-party assertion.** `tests/test_preview_csp_e2e.py:139-146,185`: `context.on('request')` only appends if URL starts `https://example.invalid/` or `wss://example.invalid/`; a request to any other origin would be ignored. The negative test probes that hostname (valid narrower evidence), but DEV's report claims zero external requests in general. **Correction:** watch all requests and check each parsed origin against the disposable `127.0.0.1:<port>` origin (including WS via Playwright's WebSocket hook where available); assert no request to non-app origins. If preserving the narrowly scoped watcher, explicitly reduce acceptance claims rather than marking global M-A5/M-A6 network isolation as proven. Also distinguish CSP-side request blocking from network/DNS failure via violation identity.

**R2-4 — Worker readiness test checks only the success flag, not a meaningful segmentation result.** `tests/test_preview_csp_e2e.py:102-114`. `worker.onmessage` accepts `data.ok===true` without asserting response ID `991` or shape/content of the resulting segment mapping. This proves a real worker message rather than just constructor return (substantive improvement), but does not fully establish the requested segmentation contract. **Correction:** verify the reply's matching message ID and minimal expected nonempty segmentation data; keep proof narrow. No new framework.
