## 2. Decision CSP-DEC-20261018-01 — preserve required functionality without pretending 001 already passed

**Existing 001 text is in direct conflict with shipped 003 integration.** The phrase *"every plugin preview kind uses ... connect-src 'none'"* and M-A5 *"preview-realm WebSocket is blocked"* cannot be fulfilled inside an editor page requiring same-origin API/WS and a Worker. Simply changing `plugin.py` to force the old policy or forcing tests to match implementation would respectively break users or conceal a security decision.

**Choose A as the smallest viable design for independent review**:

1. **Unprivileged read-only preview kinds** (.txt/.csv/other noninteractive formats, except the explicitly framed PDF variant) use the *strict 001 profile*: `default-src 'none'; script-src 'nonce-{random}'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; connect-src 'none'; base-uri 'none'; object-src 'none'; form-action 'none'`. No WS/fetch/Worker network activity authorized; prove actual browser blocking where those APIs are attempted.
2. **Interactive Markdown document** (actual `.md`/`.markdown` classified as Markdown, even while UI shows **Preview**) is an **editor-capable page**, not a sandboxed read-only Markdown preview. Use the *minimal application profile*: the same policy above with `connect-src 'self'; worker-src 'self'` replacing `connect-src 'none'`. No wildcard, third-party origin, script `'self'`, eval, inline script, `strict-dynamic`, or CDN. Require per-response nonce on **every application script**, escaped raw Markdown, strict Mermaid and local-only asset scripts. Same-origin WS/fetch/Worker are intended; cross-origin network use remains blocked. Never claim this page's WebSocket is blocked.
3. **Native PDF viewer** (read-only `.pdf` without text extraction) additionally needs `frame-src 'self'` for its own PDF iframe, while keeping `connect-src 'none'`; PDF extracted-text view uses the strict unframed profile. REVIEW must classify/limit this pre-existing exception as well, rather than hiding it under a universal regex.

Implementation remains **one composition/render function** `plugin.py::render_preview_page`; do not add a new CSP policy framework, iframe-based markdown editor, origin proxy, shadow realm, or separate Markdown renderer by default. Profiles must be selected based on **server-verified content kind**, not text sniffing for `Edit visually` or a client-supplied privilege flag.
